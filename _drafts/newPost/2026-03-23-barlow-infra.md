# 들어가며

Barlow에서 인프라 쪽으로 손댄 작업은 크게 두 가지였다. 하나는 기능 검증용 테스트 환경을 매번 수동으로 준비하던 문제, 다른 하나는 Slack/AI 기반 자동화 도구인 barlow-automation([이전 글]({% post_url 2026-03-26-agent %})에서 다룬 Human-in-the-Loop 워크플로우 시스템)을 실제로 띄울 인프라가 아예 없었던 문제다. 둘 다 "코드화되지 않은 인프라"라는 같은 뿌리에서 나온 문제였다. 실제 구현 세부사항은 [구현 문서]({% post_url 2026-03-23-barlow-infra-implementation %})에서 다룬다.

# 1. 테스트 환경: 왜 매번 손으로 만들면 안 되는가

## 1.1 상황

기능을 검증하려면 그때그때 EC2를 띄우고 DB를 세팅해야 했다. 표준화된 절차가 없다 보니 매번 조금씩 다른 환경이 만들어졌고, "테스트에서는 됐는데 왜 안 되지"류의 문제가 환경 차이에서 비롯되는 경우가 반복됐다.

## 1.2 과제

두 가지를 동시에 만족해야 했다.

- **비용**: 상시 띄워두는 환경이 아니라, 필요할 때만 띄우고 쓰지 않을 때는 자동으로 정리되는 구조
- **재현성**: 매번 같은 구성으로 뜨는 표준화된 스택

## 1.3 선택: 스팟 인스턴스 + RDS 스냅샷 복원

EC2는 온디맨드 대신 스팟 인스턴스로 선택했다. 테스트 환경은 중단되어도 재시도하면 그만이라 스팟의 변동성을 감수할 이유가 충분했고, 비용 차이가 컸다.

DB는 매번 새로 세팅하는 대신 RDS 스냅샷 복원 방식을 택했다. 최신 운영 데이터에 가까운 스냅샷에서 복원하면, 테스트 환경에서도 실제와 유사한 데이터 규모/분포로 검증할 수 있다는 게 스키마만 재현하는 방식 대비 이점이었다.

정리를 자동화하는 것도 핵심이었다. EC2 인스턴스가 종료되는 시점을 신호로 삼아, 관련 리소스(RDS 포함) 전체를 스택 단위로 정리하도록 만들었다. "다 쓰고 안 지워서 계속 돈 나가는" 흔한 문제를 아예 구조적으로 막으려는 의도였다.

# 2. barlow-automation: 인프라가 없는 상태로 배포할 수는 없다

## 2.1 상황

barlow-automation은 Slack 요청을 받아 AI로 이슈 초안을 만들고 GitHub 이슈까지 생성하는 서버리스 시스템으로 설계되어 있었다. 그런데 설계와 애플리케이션 코드는 있어도, 이걸 실제로 태울 Lambda/IAM/SQS/DynamoDB/CloudWatch/SSM 인프라는 존재하지 않았다.

## 2.2 과제

인프라를 처음부터 terraform으로 코드화하되, IAM 권한은 처음부터 넓게 잡지 않고 실제로 필요한 만큼만 점진적으로 붙이는 방향으로 가고 싶었다.

## 2.3 선택: 왜 처음부터 최소 권한을 노리지 않았나

이상적으로는 처음부터 정확한 최소 권한 스코프를 설계하는 게 맞다. 하지만 실제로는 Lambda가 어떤 리소스를 정확히 어떤 액션으로 건드리는지는 배포하고 실행해봐야 확실해지는 경우가 많았다. 그래서 택한 방식은 "필요해지는 시점마다 권한을 추가하고, 그 후 리팩터링 시점에 겹치거나 과한 권한을 정리"하는 반복이었다.

이 과정에서 deployer role의 이름을 `barlow-deployer-role`에서 `automation-deployer-role`로 바꾼 것도 같은 맥락이다. 처음엔 barlow 전체의 배포 역할처럼 이름을 지었다가, 이 role이 실제로는 automation 배포에만 쓰인다는 게 명확해지면서 이름과 실제 책임 범위를 다시 맞췄다.

# 3. 결과

테스트 환경 쪽은 CloudFormation 템플릿 하나로 표준화되어, 필요할 때 스택을 올리고 EC2 종료와 함께 자동으로 정리되는 구조가 됐다. barlow-automation 쪽은 IAM 권한을 반복적으로 좁혀가며 역할별 최소 권한 구조로 수렴시켰고, deployer role의 이름과 신뢰 정책을 실제 책임 범위에 맞게 정리했다.

기술적인 구현 세부사항(템플릿 구조, IAM 정책 변화 과정, Lambda 배포 방식)은 [구현 문서]({% post_url 2026-03-23-barlow-infra-implementation %})에서 이어진다.
