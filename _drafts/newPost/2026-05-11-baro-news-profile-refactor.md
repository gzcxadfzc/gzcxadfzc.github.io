# 들어가며

'바로' 앱에서 뉴스 카드와 정치인 프로필은 홈, 피드, 인물 상세 등 여러 화면에 걸쳐 반복적으로 등장하는 UI다. 그런데 정작 이 두 영역은 디자인 시스템 공통 컴포넌트화 작업([UI 디자인 시스템 구축 문서]({% post_url 2026-05-12-baro-design-system %}) 참고) 초기에는 정리되지 않은 채로 남아 있었다. 이 글은 News·정치인 프로필 영역을 왜, 어떻게 리팩터링했는지를 정리한 것이다. 구체적인 컴포넌트 구조 변경은 [구현 문서]({% post_url 2026-05-14-baro-news-profile-refactor-implementation %})에서 다룬다.

# 1. 상황: 무엇이 문제였나

## 1.1 언론사 로고 — URL 기반 로딩

뉴스 카드에 표시되는 언론사 로고는 `getLogoFromUrl` 방식으로, 언론사별 로고 이미지를 외부 URL에서 매번 받아오는 구조였다. 이 방식은 두 가지 문제가 있었다.

- **외부 의존성**: 로고를 제공하는 외부 소스가 응답하지 않거나 URL이 바뀌면 그대로 깨진 이미지가 노출된다.
- **로딩 지연**: 매 요청마다 네트워크를 타야 하므로, 뉴스 카드가 많이 나열되는 화면에서는 로고가 하나씩 늦게 채워지는 게 눈에 띄었다.

## 1.2 정치인 프로필 — 응집화되지 않은 UI

정치인 아바타, 리스트 로우, 원형 테두리 처리 같은 요소들이 화면마다 개별적으로 구현되어 있어서, 한 곳에서 발견된 버그(예: 원형 테두리가 잘못 노출되는 문제)가 다른 화면에는 반영되지 않는 일이 반복됐다.

## 1.3 News 컴포넌트 자체의 산발적 구조

뉴스 카드 레이아웃, shimmer 로딩 처리, 아코디언 아이콘 등이 하나의 컴포넌트로 묶여있지 않고 여러 곳에 흩어져 있어서, 뉴스 관련 UI를 수정할 때마다 영향 범위를 예측하기 어려웠다.

# 2. 과제

이 리팩터링에서 확정해야 했던 것은 두 가지였다.

1. 언론사 로고를 **외부 의존성 없는 방식**으로 바꾸는 것
2. News/정치인 관련 UI를 **재사용 가능한 컴포넌트 단위로 응집화**하고, 마침 병행 중이던 [디자인 시스템 구축]({% post_url 2026-05-12-baro-design-system %}) 컨벤션에 맞추는 것

# 3. 판단: 왜 이 방향을 택했나

## 3.1 로고는 로컬 SVG로

언론사 수가 무한히 늘어나는 게 아니라 제한적이고 잘 바뀌지 않는 목록이라는 점에 착안해서, `getLogoFromUrl`을 걷어내고 로고를 로컬 SVG 에셋으로 번들에 포함시키기로 했다. 네트워크 왕복이 아예 사라지므로 로딩 지연 문제와 외부 의존성 문제를 동시에 해결하는 방향이다.

## 3.2 컴포넌트는 역할 단위로 추출

정치인 프로필 쪽은 통으로 리팩터링하기보다, `PressLogo`(언론사 로고 표시), `PoliticianAvatar`(정치인 프로필 이미지) 처럼 역할이 분명한 단위로 먼저 추출한 뒤, 이걸 다시 `PoliticianListRow`처럼 더 큰 단위에 조합해 넣는 순서를 택했다. 작은 단위부터 추출해야 어디서 발생한 버그(원형 테두리 노출 문제 등)를 고쳤을 때 그 수정이 모든 사용처에 자동으로 퍼진다.

News 쪽도 마찬가지로, 레이아웃 개선과 shimmer 로딩 개선을 개별 컴포넌트 단위로 진행한 뒤 `News` 컴포넌트로 응집시켰다.

# 4. 결과

언론사 로고 표시 방식을 로컬 SVG로 전면 전환해 외부 URL 의존성을 제거했고, `PressLogo`/`PoliticianAvatar`를 포함한 재사용 컴포넌트들을 추출해 화면 간 UI 일관성을 확보했다. 이 작업은 병행 중이던 디자인 시스템 구축과 같은 시기에 진행되어, 정치인 컴포넌트에 디자인 시스템의 `Accordion` 같은 공통 프리미티브를 바로 통합할 수 있었다.

기술적인 변경 세부사항은 [구현 문서]({% post_url 2026-05-14-baro-news-profile-refactor-implementation %})에 정리했다.
