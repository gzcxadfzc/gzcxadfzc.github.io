# 들어가며

[설명 문서]({% post_url 2026-05-11-baro-news-profile-refactor %})에서 다룬 News·정치인 프로필 리팩터링의 실제 구현 내용을 정리한다.

# 1. 언론사 로고: URL → 로컬 SVG

기존에는 `getLogoFromUrl(pressName)`처럼 언론사 이름/코드를 받아 외부에서 로고 이미지 URL을 조합하는 함수가 뉴스 카드 렌더링 경로에 직접 물려 있었다.

이를 걷어내고, 언론사 로고를 로컬 SVG 에셋으로 번들에 포함시킨 뒤 `PressLogo` 컴포넌트로 추출했다.

```
# 변경 전
News Card → getLogoFromUrl(press) → <Image src={remoteUrl} />

# 변경 후
News Card → <PressLogo press={press} /> → 로컬 SVG 에셋 매핑
```

`PressLogo`는 언론사 식별자를 로컬 SVG 에셋 맵으로 매핑하기만 하면 되므로, 네트워크 요청이 렌더링 경로에서 완전히 빠진다. 매핑에 없는 언론사가 들어오는 경우를 대비한 기본 아이콘(fallback)도 함께 정의했다.

# 2. News 컴포넌트 응집화

뉴스 카드 레이아웃 개선, shimmer 로딩, 아코디언 아이콘 교체가 개별 커밋으로 진행된 뒤, 이 요소들을 하나의 `News` 컴포넌트로 응집시키고 타임라인 형태의 표시가 필요한 곳에는 디자인 시스템의 `Stepper` 컴포넌트를 적용했다.

- shimmer 로딩: 로고/카드 콘텐츠가 준비되기 전 스켈레톤 형태로 표시해, 로컬 SVG 전환 이후에도 초기 렌더 시점의 레이아웃 시프트를 방지
- 아코디언 아이콘: 기존 개별 이미지 대신 SVG 아이콘으로 교체해 News 컴포넌트 내부에서 일관되게 관리

# 3. 정치인 컴포넌트 추출

## 3.1 PressLogo / PoliticianAvatar 분리

정치인 프로필 이미지 표시 로직을 `PoliticianAvatar` 컴포넌트로 별도 추출했다. `PressLogo`와 마찬가지로 "이미지를 어떻게 가져오고 표시할지"를 컴포넌트 내부로 캡슐화해서, 사용하는 쪽(리스트, 상세 화면 등)은 정치인 식별자만 넘기면 되도록 인터페이스를 단순화했다.

## 3.2 원형 테두리 노출 버그

`PoliticianAvatar`를 여러 화면에서 공유하는 과정에서, 특정 화면 조합에서만 원형 테두리(border-radius 처리)가 잘못 노출되는 버그가 발견됐다. 컴포넌트가 추출되기 전에는 화면마다 개별 구현이라 이런 버그가 특정 화면에만 국한됐지만, 반대로 화면마다 따로 고쳐야 했다. 추출 이후에는 `PoliticianAvatar` 한 곳만 수정하면 모든 사용처에 반영되므로, 이번 버그 수정을 계기로 공통 컴포넌트화의 실익을 다시 확인했다.

## 3.3 PoliticianListRow 통합

`PoliticianAvatar`를 `PoliticianListRow`(정치인 리스트 항목) 안에 통합해서, 리스트 화면에서 정치인 항목을 렌더링할 때 아바타 표시 방식이 항상 동일하게 유지되도록 했다.

## 3.4 디자인 시스템 Accordion 통합

정치인 상세 정보(경력, 이력 등 접고 펼 수 있는 영역)에는 병행 중이던 [디자인 시스템 구축]({% post_url 2026-05-12-baro-design-system %})에서 나온 `Accordion` 컴포넌트를 그대로 가져다 썼다. 정치인 컴포넌트 리팩터링 시점과 디자인 시스템 프리미티브 구축 시점이 겹쳤기 때문에, 별도의 Accordion을 직접 구현하지 않고 바로 재사용할 수 있었다.

# 4. 부수적으로 함께 처리한 것

- 재산 총액 표기를 숫자 그대로 노출하던 방식에서 한글 금액 표현(예: "3억 2천만원" 형태)으로 변경하고, 이 변환 로직을 별도 함수로 리팩터링해 재사용 가능하게 만들었다.
- 리팩터링 과정에서 실수로 빠졌던 `IconNewspaper` 아이콘을 복원했다.

# 5. 정리

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 언론사 로고 | `getLogoFromUrl` (외부 URL) | `PressLogo` (로컬 SVG) |
| 정치인 아바타 | 화면별 개별 구현 | `PoliticianAvatar` 공통 컴포넌트 |
| 뉴스 UI 구조 | 레이아웃/로딩/아이콘 산발적 구현 | `News` 컴포넌트로 응집, `Stepper` 적용 |
| 접고 펼치는 UI | 개별 구현 | 디자인 시스템 `Accordion` 재사용 |

작은 단위(PressLogo, PoliticianAvatar)로 먼저 추출하고 이를 더 큰 컴포넌트(PoliticianListRow, News)에 조합해 넣는 순서를 택한 덕분에, 원형 테두리 버그처럼 여러 화면에 흩어져 있던 문제를 한 곳만 고쳐서 해결할 수 있었다.
